# SAA Internet Watchlist URL Creator Implementation Plan

Date: 2026-09-04

## Objective

Implement a deterministic C++ watchlist compiler that creates curated URLs,
validates source ownership and compliance declarations, performs non-mutating
preflight checks, and registers eligible watches with immutable provenance.

## Implementation sequence

1. Define a source-group registry with controlling publisher, evidence group,
   hostname allowlist, template allowlist, MIME limits, polling defaults,
   extraction strategy, and license expectation.
2. Define a versioned JSON Schema for editable watchlist manifests.
3. Implement trusted URL templates and exact-URL normalization in the sources
   library.
4. Implement semantic validation for duplicate names and canonical URLs,
   source-group hostname ownership, supported MIME types, polling limits, and
   complete robots and license declarations.
5. Implement non-mutating HTTP preflight with robots, redirects, TLS, MIME,
   response size, authentication, and rate-limit reporting.
6. Register derived source policies and runtime watches idempotently while
   keeping enablement conditional on deterministic eligibility.
7. Register an immutable `internet-watch-registration` record binding the
   watch to the manifest, entry, policy, preflight report, publisher, tier,
   purpose, subject, and license evidence.
8. Bind verified watchlist license evidence into automatic source assessment;
   unresolved entries require a known license and cannot advance as `UNKNOWN`.
9. Add focused unit and CLI smoke tests using local or fake providers.
10. Validate the expanded starter manifest and resource integrity manifest.

Registration supports `dry_run`, `source_groups`, and the idempotent `resume`
action. A dry run computes the exact policy, watch, and provenance IDs without
creating a workspace or writing durable records.

## Deterministic lifecycle

```text
DRAFT
  -> VALIDATED
  -> PREFLIGHT_ELIGIBLE | QUARANTINED | DEFERRED_RATE_LIMIT
  -> REGISTERED_DISABLED | REGISTERED_ENABLED
```

There is no human approval state. Enablement requires an explicit manifest
request, an explicit registration enable flag, and a fresh eligible preflight
result. Unresolved entries are never enabled automatically.

## Completion evidence

- The seven DLMF sections are reproducibly generated by the
  `nist-dlmf-section` template.
- Invalid templates, duplicate names or URLs, mismatched publishers, unknown
  source groups, unapproved hosts, and unsupported MIME types are rejected.
- Preflight never writes runtime records and emits a manifest-bound report.
- Registration creates deterministic source-policy, watch, and provenance
  records and is idempotent.
- Review-required licenses derive `require_known_license=true`.
- Verified registration evidence supplies the automatic source-assessment
  license classification instead of `UNKNOWN`.
- Focused tests and the CLI smoke test pass without live internet access.
